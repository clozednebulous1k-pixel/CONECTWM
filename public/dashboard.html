Diretrizes de Segurança para Desenvolvedores

Boas práticas cruciais para evitar vazamentos de dados, exploits e manter seu SaaS blindado.

Vazamento de Credenciais (.env)

Nunca commite seus arquivos .env no GitHub. Chaves de API expostas (como OpenAI, Stripe ou bancos de dados) podem ser detectadas em segundos por rastreadores maliciosos, gerando prejuízos financeiros imediatos.

Recomendação: Crie sempre um arquivo .env.example para mostrar quais variáveis são necessárias, e adicione .env no seu .gitignore.

Prevenindo SQL Injection

Ocorre quando comandos SQL são inseridos diretamente em campos de input. Se você concatenar strings de entrada diretamente nas consultas de banco de dados, invasores poderão executar comandos arbitrários, ler ou apagar dados.

Recomendação: Utilize parametrização de consultas (Prepared Statements) ou ORMs seguros (como Prisma, Sequelize ou Mongoose) para isolar completamente as strings dos comandos SQL.

Configuração de CORS Rígida

Habilitar Cross-Origin Resource Sharing (CORS) com o curinga * permite que qualquer site na internet envie requisições para a sua API e leia as respostas dos usuários, facilitando ataques de falsificação de requisições.

Recomendação: Configure sua API para aceitar requisições de origens específicas (ex: https://conectwm.com.br) e recuse conexões externas genéricas.

Limitação de Requisições (Rate Limiting)

Seus endpoints de inteligência artificial (que gastam tokens caros da OpenAI) ou telas de login precisam de limites. Sem rate limiting, bots podem fazer milhares de requisições rápidas para derrubar o servidor ou consumir seus fundos de API.

Recomendação: Adicione pacotes de limitação (como express-rate-limit) para bloquear temporariamente IPs que excedam requisições permitidas em um intervalo.
